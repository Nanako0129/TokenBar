## Before you update

**TokenBar is now Syrtis, and the first launch renames the app on disk.** [#392](https://github.com/Nanako0129/syrtis/pull/392) [#395](https://github.com/Nanako0129/syrtis/pull/395) [#390](https://github.com/Nanako0129/syrtis/pull/390)

The update installs over `TokenBar.app`. On its first launch the app renames itself to `Syrtis.app` in the same folder and starts again from there. The bundle identifier has not changed, so settings, usage history and the login item carry over.

If `TokenBar.app` is pinned in the Dock, the tile is repointed at `Syrtis.app` and the Dock restarts once. Two things follow from that restart. Windows you had minimized to the Dock leave it; clicking their app brings them back. The pinned tile may keep the old icon until you click it once.

On an account that cannot write to the Applications folder, the rename is skipped. The app keeps the file name `TokenBar.app` and works the same.

**Homebrew has a new tap.** New installs use `brew install --cask nanako0129/tap/syrtis`. An existing install from `nanako0129/tokenbar` keeps updating through the app itself; that cask stays on the last TokenBar release.

**Some clients re-scan once, and two of them count differently.** [#386](https://github.com/Nanako0129/syrtis/pull/386) [#389](https://github.com/Nanako0129/syrtis/pull/389)

The engine moves forward, and Copilot, Grok, OpenClaw, RooCode, KiloCode, Cline, Cursor, OpenCode, Pi and Droid each rebuild their cache once on the first launch. Every other client, Claude and Codex included, is read from its existing cache.

- **Pi counts fall if you fork sessions.** A forked session copies the parent's replies into the new file with the same response id, and each copy was counted again. Each reply now counts once.
- **OpenClaw counts can move either way.** Archived sessions (`.jsonl.zst`) are now read, which adds usage that was missing, and compaction checkpoints are no longer counted as usage.

Droid totals are unchanged: a session's usage is now split across its replies instead of landing as one record. Cursor's `Input (w/ Cache Write)` is now counted as cache write, and a `$0.00` cost Cursor reports is kept as $0.00.

## Features

- **On macOS 27, the dashboard opens in a Liquid Glass panel.** [#380](https://github.com/Nanako0129/syrtis/pull/380) [#391](https://github.com/Nanako0129/syrtis/pull/391)

  The popover blurred the desktop before the dashboard could see it, so its glass could only show a flat tone. The panel's glass refracts the actual wallpaper. It closes on Esc or a click anywhere else, and right-clicking the menu bar item still opens the menu. Tab selections slide, bar charts regrow and heatmaps crossfade between views. Below macOS 27 the popover is unchanged.

- **A new icon and name in the app.** [#392](https://github.com/Nanako0129/syrtis/pull/392)

  The panel header shows the Syrtis mark and the Greek wordmark Σύρτις, the Settings sidebar uses the same mark, and Discord presence shows the new icon. The site is now [syrtis.nyanako.com](https://syrtis.nyanako.com), with a page on [where the name comes from](https://syrtis.nyanako.com/why-syrtis/). Old links to the TokenBar site and repository redirect.

## Fixes

- **A quota window's readings were deleted when they could not be modelled.** [#373](https://github.com/Nanako0129/syrtis/pull/373) — relates to [#370](https://github.com/Nanako0129/syrtis/issues/370)

  History kept only the windows a pace curve could be fitted to. When a provider moved a reset later, the window's recorded reset no longer qualified, and its readings were erased: on the store behind #370, two weekly windows of 51 readings each. They are now kept. They still do not feed the pace model.

- **Codex asked you to sign in again while a refresh token was available.** [#344](https://github.com/Nanako0129/syrtis/pull/344) — thanks [@snowman12320](https://github.com/snowman12320)

  Codex access tokens can expire before the eight-day interval TokenBar used to decide when to refresh them. The token's own expiry is now checked, and it is refreshed within five minutes of it.

- **Switching windows on the quota window card paused the app.** [#383](https://github.com/Nanako0129/syrtis/pull/383)

  Each switch re-read the whole quota history once per part of the card that wanted it: 131–144 ms on the main thread in a release build. Each series is now read once per update, and a switch takes 12–15 ms.

- **Opening the dashboard right after launch computed the usage graph up to three times.** [#384](https://github.com/Nanako0129/syrtis/pull/384)

  Requests that arrive while the graph is being computed now wait for that result. In three paired runs on real data, the graph was ready after 2.4, 2.2 and 2.1 s, down from 5.6, 3.7 and 4.6 s.

- **The Local Network prompt did not say why it appeared.** [#374](https://github.com/Nanako0129/syrtis/pull/374) — thanks [@mvanhorn](https://github.com/mvanhorn)

  macOS can ask for local network access when a VPN routes provider traffic through a local network. The prompt now explains that Syrtis connects to your providers to read quota information.
