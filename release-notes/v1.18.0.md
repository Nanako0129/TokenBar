## Before you update

**Codex turn counts jump from zero to thousands, and the first launch rescans Codex transcripts once.** [#315](https://github.com/Nanako0129/TokenBar/pull/315)

Codex used to announce a human turn as an `event_msg` of type `user_message`. Around version 0.145 it stopped, and now reports the same input as an `item_completed` carrying a `UserMessage` item. TokenBar recognised only the old shape, so `is_turn_start` never fired on a recent transcript and the Daily and Monthly cards read `0 turns` for Codex on essentially every day.

**Nothing was recounted.** On every day with Codex activity, every other figure is byte-identical before and after — tokens, cost, messages, models. Only the turn column moves, which is what makes this checkable: the number that was wrong is the only one that changed.

Reading turns out of the old cache is not possible, so `parser_version` for Codex moves 5 to 6 and every Codex shard is rebuilt once on first launch. No other client's cache is touched — Claude, Copilot, Gemini and the rest are read from their existing shards as usual. The launch after it is normal speed.

## Features

- **The paid OpenCode Go plan now has a quota card.** [#301](https://github.com/Nanako0129/TokenBar/pull/301) — thanks [@binhonglee](https://github.com/binhonglee)

  OpenCode stores the Go plan under a separate api key, and TokenBar read only the Copilot quota that lives in the same `auth.json`. Its rolling, weekly and monthly windows now appear under the existing `opencode` client rather than as a new tab, the same arrangement the Copilot quota already uses.

- **Kiro's monthly allowance now appears as a quota card.** [#305](https://github.com/Nanako0129/TokenBar/pull/305) — thanks [@binhonglee](https://github.com/binhonglee)

  Kiro was already recognised as a subscription for attribution, but no quota was ever fetched for it, so the plan had no usage bar. The token is discovered from either the kiro-cli store or the Kiro IDE token file.

- **Grok Bot's weekly allowance now appears alongside Grok Build's.** [#316](https://github.com/Nanako0129/TokenBar/pull/316) — thanks [@savourylie](https://github.com/savourylie)

  The two are separate allowances and only Grok Build's was read. Both now appear together under a **Grok Build & Bot** tab in Overview and Quota, including on machines with no local Grok usage records at all.

  **Reading that allowance needs your permission once.** [#338](https://github.com/Nanako0129/TokenBar/pull/338)

  Grok Bot keeps its login in your Keychain, and the weekly limit cannot be read without decrypting it. Rather than letting macOS ask out of nowhere, the card says what it needs and waits. **Allow** proceeds, and the system dialog follows a second or two later; **Not now** leaves the card as a single grey line, with Allow still there whenever you change your mind. If macOS itself refuses, or never answers, the card says so and TokenBar stops asking rather than raising the dialog again every cycle — Allow tries once more when you want it to.

  The login is used for one thing: asking Grok Bot's usage endpoint (`api2.cursor.sh`) what your weekly limit is. TokenBar does not store it, does not log it, and sends it nowhere else. Declining affects that card and nothing else — there is no setting to find and nothing to undo later, because once macOS holds the grant only macOS can withdraw it.

  Having Grok Bot signed in already does not change this: the card still asks, and macOS may still want to confirm. Reading the item is what this integration does for the first time in this release, so there is no prior grant to rely on, and TokenBar cannot check for one without performing the read it is asking about — asking macOS whether it would allow the read *is* the read.

- **Window history grows past twelve rows.** [#334](https://github.com/Nanako0129/TokenBar/pull/334)

  The card drew twelve cycles with no way to reach the thirteenth. It still opens at twelve, and a `Show N more` link under the list adds twelve per press until every cycle is on screen. Pressing to exhaustion reaches 32, which is where the engine's fold stops.

## Fixes

- **A quota poll could open a browser tab you never asked for.** [#332](https://github.com/Nanako0129/TokenBar/pull/332) — reported by [@banahaker](https://github.com/banahaker) in [#329](https://github.com/Nanako0129/TokenBar/issues/329)

  `agy --print` is documented as non-interactive and is not: with an expired token and no DNS, it treats the network failure as an authentication failure and starts an interactive sign-in, which opens a tab. The defect is the CLI's, but TokenBar is the only thing invoking it unattended, and its timer fires exactly when that path is most likely. TokenBar now resolves the endpoint first and gives up without invoking the CLI when that fails.

- **A window-history card said usage was never recorded, about usage sitting in the same scan.** [#322](https://github.com/Nanako0129/TokenBar/pull/322)

  Two different statements were collapsed into one flag: *this machine recorded nothing*, and *this machine recorded it and you have not said which subscription it belongs to*. Three places computed that flag, each the same wrong way, so a client you had not classified was reported as having no records at all. The flag is now decided per subscription.

- **One long model name stretched a whole usage card past the edge of the popover.** [#336](https://github.com/Nanako0129/TokenBar/pull/336) — reported in [#335](https://github.com/Nanako0129/TokenBar/issues/335)

  The layout measured every legend item at its ideal width and took the widest row as the card's own width, so a single entry wider than the popover stretched everything around it. Locally-served model names reach that length easily — the report had one running to `hauhaucs/qwen3.8-27b-uncensored-…`. Items are now measured against the row they sit on, which lets the label's single-line truncation do the job it was already there to do.

- **An OpenCode Go window could be dated to a cycle that had already reset.** [#327](https://github.com/Nanako0129/TokenBar/pull/327)

  The clock was read on the first line of the fetch and held across the credential load and the HTTP round trip, so a reset that expired while the request was in flight still compared as being in the future. The clock is now read after the response arrives.

- **A cancelled quota poller kept running for the rest of its minute.** [#331](https://github.com/Nanako0129/TokenBar/pull/331)

  Closing the popover cancels the poller, but the sleep it was parked in observed only its own timeout, so the task stayed alive for up to a minute after the window it served had gone. Nothing observable went wrong, which is why it lasted: the work was not incorrect, only late to stop.

- **Engine update: two window-shape corrections.** [#328](https://github.com/Nanako0129/TokenBar/pull/328)

  A reversed or empty window now yields an empty list rather than an error, and the message filter is aligned with the aggregate it feeds. For macOS this is a pin advance only — the cache format and every parser version are unchanged, so nothing goes cold and nothing is rescanned on account of it. The one rescan in this release is the Codex one described at the top.
